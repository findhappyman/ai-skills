# 图片生成指南

目标：为审核包生成真实可用的封面图、段落配图和信息图。不能只写 prompt。

## 必需图片

- `<主题>_封面图.png`
- `<主题>_段落配图_01.png`
- `<主题>_段落配图_02.png`
- `<主题>_信息图.png`

图片生成后必须复制到 run 目录并使用稳定文件名。推进到 `article_assets_ready` 前，确认文件存在、非空、尺寸可读；信息图还必须视觉打开检查中文是否可读。

## 通用原则

- 图片服务文章理解，不做纯装饰。
- 优先展示关键物件、核心场景、流程隐喻或章节关系。
- 默认不要人物面部特写，不生成可识别真人。
- 如果用户配置 `AUTHOR_VISUAL_PROFILE`，可按该描述生成非敏感的作者化身；否则不要硬编码任何人的年龄、姓名、职业或外貌。
- 不放二维码、账号 ID、真实域名、真实 handle、头像徽标或 API 信息。
- 文字少而清楚，中文必须可读。

## 封面图

封面图应该回答：读者一眼能不能知道这篇文章的核心矛盾或关键场景？

推荐 prompt 结构：

```text
一张适合中文长文封面的横版插图。主题：[文章主题]。
核心画面：[一个具体物件/场景/流程隐喻]。
视觉风格：[克制、现代、清晰、非营销海报]。
要求：不要出现真实姓名、网站、账号、二维码、logo；不要人物面部特写；不生成难以辨认的小字。
```

## 段落配图

每张段落配图对应一个主要小节，必须解释该小节的关系或动作。

```text
一张服务文章小节的中文插图。小节标题：[小节标题]。
要解释的关系：[观点关系]。
画面：[具体场景/物件/动作]。
要求：与封面图视觉系统一致；少文字；不放任何账号或真实链接。
```

## 信息图

信息图默认是公众号文末总结长图。它必须覆盖最终正文所有主要小节，尤其不能遗漏最后的总结、复盘或行动小节。

推荐结构：

- 大标题：文章核心结论。
- 副标题：一句解释。
- 3-5 个编号分区：数量和正文主要小节一致，或能完整覆盖所有主要小节。
- 每个分区包含短标题、关键词、图标/物件/流程。
- 底部结论条：一句可截图传播的结论。

信息图 prompt：

```text
生成一张中文科技信息长图，竖版，适合微信公众号文末总结。
主题：[文章主题]
大标题：[核心标题]
副标题：[一句解释]
分区：
01 [小节一] - [短说明]
02 [小节二] - [短说明]
03 [小节三] - [短说明]
04 [小节四] - [短说明]
底部结论：[一句结论]
视觉要求：清晰编号分区、图标或物件流程、底部结论条、中文可读。
禁止：二维码、账号、真实域名、真实 handle、营销关注引导、无意义小字。
```

## 插入位置检查

- 公众号 HTML：信息图在最后一个正文小节之后。
- X 发布版 Markdown：信息图 Markdown 在最后一个正文小节之后。
- 网站版 Markdown：信息图路径在最后一个正文小节之后。
- 总览和审核版：写清信息图覆盖哪些章节、插入在哪里。

如果信息图遗漏最后一点、文字错误严重或插入位置不对，重生成受影响图片并覆盖稳定文件名，同时更新所有平台稿和状态文件。
